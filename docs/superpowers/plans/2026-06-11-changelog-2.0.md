# CricStats — Version 2.0 Changelog & Cross-Verification Report

This document details the cross-verification analysis comparing the local **Version 2.0** codebase against the existing version hosted on GitHub (`origin/main`, commit `883de107`). 

Over the course of the v2.0 development cycle, several major features have been added, outdated mockup files have been cleaned up and archived, database schemas have been canonicalized, and the frontend design system has been fully rewritten for premium glassmorphism and theme adaptation.

## 2. Added Features (New Capabilities)

### 📊 Dynamic Stat Builder (BI Module)
*   **Backend (`api/stat_builder.py`):** Added a dynamic SQL query builder compiling on-the-fly CTE queries from custom frontend filters.
*   **Team Results & Standings:** Added capability to query team outcomes directly from `matches`, displaying games played, wins, losses, ties, and win percentage leaderboards.
*   **Advanced Filtering:** Added batting position, dismissal types, `is_not_out` filters, over ranges, and day/night toggles.
*   **Frontend (`web/app/stat-builder/`):** Full-screen workspace with collapsible accordion filter panel, smart URL query parameter serialization, and custom results grid.

### 🧩 Entity Canonicalization Engine
*   **Logic (`ingestion/entity_resolver.py`, `api/entity_resolution.py`):** Automatically matches team name variants (e.g., *Royal Challengers Bangalore* vs. *Royal Challengers Bengaluru*) and venue changes (e.g., *Feroz Shah Kotla* vs. *Arun Jaitley Stadium*) to stable canonical IDs.
*   **Database Seeding (`db/populate_entities.py`, `ingestion/entity_aliases.json`):** Pre-loaded canonical index with fallback logic. Log candidate aliases that fail auto-matching into a review table.
*   **Backfill Scripts (`db/backfill_entities.py`):** Backfilled existing matches/innings records to utilize canonical ID columns.

### 📅 "On This Day" in Cricket
*   **API Endpoint (`/api/v1/on-this-day`):** Fetches all historical matches played on the current calendar date (up to 20 matches) using PostgreSQL month/day extractions.
*   **Frontend Component (`OnThisDayCard`):** A custom homepage card displaying a scrollable vertical list of historical matches, complete with winner details, margins, venues, and a "Years Ago" indicator.

### 🆚 Player-vs-Team Analytics Dashboard
*   **API Endpoint (`/api/v1/player-vs-team`):** Direct head-to-head statistics mapping a single player's career performance against a chosen team (batting and bowling).
*   **Frontend Route (`/player-vs-team`):** Side-by-side splits with format filters and interactive charts.

## 3. Improved & Enhanced Features (Revamps)

### 📈 Interactive Match Card & Run Progression Chart (v3)
*   **2D Pan & Zoom Engine:** Replaced basic CSS charts with a fully mathematical 2D SVG charting engine in `web/components/ui/RunsChart.tsx`.
*   **Interactivity:** Added wheel scroll-to-zoom (scales both X and Y relatively), click-and-drag panning, and double-click to reset view to 100%.
*   **Data Annotations:** Plotted cumulative runs, over markers, and Fall of Wicket (FOW) dots dynamically. Zoomed charts use `<clipPath>` masks to prevent boundary overflows.

### 📂 Matches Archive Module
*   **Three-Panel Layout (`web/app/matches/`):** Rebuilt layout matching premium design principles.
*   **Month Timeline Density Widget:** Displays monthly match volumes using side-by-side vertical pillars (color-coded by International, League, or ICC flags) instead of stacked horizontal blocks.
*   **Abbreviation Search Parser:** Automatically maps abbreviation tokens (`rcb`, `csk`, `ind`, `aus`) and splits matchups (`rcb vs csk`) to query the API dynamically.
*   **Host Country Resolver:** Maps stadium cities to canonical countries inside the API to clean up missing host filters.

### 🏆 Team H2H Top Performers
*   **Endpoints (`/teams/h2h/top-batters` and `/top-bowlers`):** Queries matches between two teams to find the top 10 historical run-scorers and wicket-takers.
*   **Frontend Integration:** Added Top Performers grid blocks on the `/teams` page linking directly to player profiles.

### 📈 Phase Specialists & Form Guide Filters
*   **Phase Specialists:** Auto-detects powerplay/middle/death specialists on the backend based on strike rate/economy deviations, rendering gold badges in player headers.
*   **Form Guide:** Added format pills above the form guía strip (All, IPL, T20, IT20, ODI, ODM, Test) for dynamic filtering.

## 5. Database Schema & Query Optimizations

### 🗄️ Database Alterations (`db/schema.sql`, `db/entity_aliases.sql`)
```sql
-- Added Match Metadata
ALTER TABLE matches ADD COLUMN match_stage VARCHAR(50);
ALTER TABLE matches ADD COLUMN match_number INTEGER;
ALTER TABLE matches ADD COLUMN match_group VARCHAR(50);

-- Added Entity Canonicalization Tables
CREATE TABLE teams (team_id TEXT PRIMARY KEY, canonical_name VARCHAR(120)...);
CREATE TABLE team_aliases (team_id TEXT NOT NULL REFERENCES teams(team_id)...);
CREATE TABLE venues (venue_id TEXT PRIMARY KEY, canonical_name VARCHAR(150)...);
CREATE TABLE venue_aliases (venue_id TEXT NOT NULL REFERENCES venues(venue_id)...);
CREATE TABLE entity_alias_candidates (...);

-- Added ID columns linking to canonical entities
ALTER TABLE matches ADD COLUMN team1_id VARCHAR(80), team2_id VARCHAR(80), winner_id VARCHAR(80), venue_id VARCHAR(120);
ALTER TABLE innings ADD COLUMN batting_team_id VARCHAR(80), bowling_team_id VARCHAR(80);
```

### ⚡ Materialized View Improvements (`db/materialized_views.sql`)
*   **Removed ad-hoc normalise_team():** Since team and venue names are normalized at ingestion time, the slow PL/pgSQL function `normalise_team()` was removed from materialized view definitions, drastically speeding up queries.
*   **Format normalization:** Explicitly mapped T20 bilateral series and IT20 format records under a single normalized `'T20I'` format bucket (while keeping IPL isolated).
*   **Super Over Safeguards:** Added `i.innings_number <= 2` clauses to `mv_stat_cards` to prevent Super Over runs and wickets from polluting all-time career thresholds.

## 6. UI/UX & Design System Transformation

The user interface was completely overhauled to create a state-of-the-art visual presentation:

1.  **CSS Glassmorphism Design System (`web/app/globals.css`):**
    *   Introduced standard tokens for glass cards: `var(--glass-bg)`, `var(--glass-border)`, and `var(--card-hover)`.
    *   Implemented floating ambient particles and background radial glows (`.radial-glow`).
    *   Added micro-animations (translateY jumps, glow transitions, SVG pulse effects) for all interactive cards and list items.
2.  **Seamless Light Mode Support:**
    *   Replaced hardcoded dark themes (`data-theme="dark"` / `bg-[#0d0f14]`) with adaptive CSS variables.
    *   Modified avatars (`.pav-v2`), floating stats pills (`.hsp-v2`), and spotlight headers to dynamically flip colors between dark and light themes using the `ThemeToggle.tsx` component.
3.  **Modern Component Replacements:**
    *   Upgraded buttons, badges, scrollbars, and inputs with smooth borders and subtle shadows.
    *   Replaced generic spinners with animated gradient shimmer skeletons during client-side fetches.
